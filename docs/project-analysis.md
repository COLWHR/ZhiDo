# ZhiDo / MADF 项目技术剖析：技术路线 · 核心亮点 · 优势 · 意义

> 版本：V1.2.1 ｜ 剖析口径：基于当前代码与实测回归结果，不含未落地的规划功能。

## 一、项目定位

ZhiDo（MADF）是一个面向研讨、教育与头脑风暴场景的**多智能体协作 Web 平台**：用户创建专家型智能体，围绕主题组织圆桌讨论、团队协作或一对一持续对话，系统负责发言调度、意图路由、产物生成、成本治理与过程留痕。

一句话概括：**云端大模型负责内容生成，本地规则与轻量小模型负责决策路由与兜底，平台把多智能体协作做成了一套可部署、可评测、可追溯的完整工程闭环。**

### 三种协作形态

| 形态 | 入口 | 交互机制 |
| --- | --- | --- |
| 圆桌论坛 | 主持人 + 嘉宾智能体 | 调度器打分选人，WebSocket 直播发言，观众可插话注入 |
| 团队群聊 | 多成员智能体群组 | @ 成员才回复，多成员上下文接力，产物挂同一条消息 |
| 时空之门单聊 | 用户 ↔ 单个智能体 | 持续对话、历史持久化、图片可进入多模态上下文 |

## 二、技术路线

### 2.1 总体技术栈

- **前端**：Vue 3 + TypeScript + Vite + Pinia + Vue Router + Ant Design Vue；SSE / WebSocket 流式渲染、@ 提及弹层、附件卡片、浏览器端语音朗读。
- **后端**：FastAPI + Uvicorn，REST API + 实时推送；JWT 鉴权；服务分层（端点 → 编排服务 → 决策/规则/大模型 → 数据层）。
- **数据层**：libsql（SQLite）/ PostgreSQL 双库兼容；可选 Redis 缓存；独立附件与产物库。
- **模型层**：云端大模型（GLM 系列）承担文本生成与图片理解；**本地不部署深度学习模型**。
- **质量保障**：后端 Pytest，前端 Vitest；当前回归基线后端 159 passed、前端 37 passed / 1 skipped。

### 2.2 分层架构

```text
浏览器（Vue3 + Ant Design Vue）
  │  HTTP / SSE / WebSocket
  v
API 端点层（auth / personas / forums / teams / agents / decision / admin …）
  │
  v
编排服务层
  ├─ forum_scheduler   圆桌发言调度（规则加权打分）
  ├─ team_orchestrator 团队群聊编排（@ 触发、上下文接力、截断）
  ├─ skill_runtime     技能路由、消息组装、本地产物渲染
  ├─ credit_service    积分估算 / 预检 / 扣费
  ├─ knowledge_service 智能体知识库挂载
  └─ decision router   意图路由小模型 + 三层兜底
  │
  ├─ 本地决策：规则基线 / TF-IDF + 朴素贝叶斯（CPU，离线可推理）
  ├─ 云端大模型：文本生成、多模态图片理解
  └─ 数据层：用户 / 智能体 / 论坛 / 团队 / 消息 / 产物 / 积分流水 / 审计 / 决策日志
```

### 2.3 决策路线的演进

- **第一阶段**：意图与产物类型完全依赖正则关键词规则 + 大模型提示词，本地无可训练、可评测的决策模块。
- **第二阶段（本次）**：补齐本地可训练的意图路由小模型，建立「模型达标 → 规则兜底 → 大模型仲裁上游」的三层链路，并把每次决策落审计、做可解释面板。
- **路线原则**：纯 CPU 可训练、离线可演示、指标可复算、模型接口可插拔；待真实标注样本积累后，可平滑替换为更强分类器而不动上层业务。

## 三、核心亮点

### 3.1 三种形态覆盖完整协作链路

- **圆桌论坛调度**：调度器对候选智能体做规则加权打分，综合考量：角色优先级、与近期上下文的共享词、是否处于提问/追问回合、回合模式匹配（回答 / 澄清 / 质疑 / 总结 / 过渡）、发言新颖度，以及重复发言惩罚（刚发言者大幅降分、本轮已发言者降分、间隔过短惩罚）。发言过程通过 WebSocket 近似直播呈现，观众插话会重新组织后续发言。
- **团队群聊省成本设计**：未 @ 成员不调用大模型；@ 解析支持输入框弹层、实时过滤、点选插入、键盘导航；多成员之间按顺序接力，后发言者能看到同轮前面成员的回复；进模型前截断最近上下文并过滤 system 消息。
- **单聊持续记忆**：对话历史持久化，图片 URL 可纳入多模态上下文。

### 3.2 分层决策内核（本次重点）

- **小模型**：TF-IDF 字符级 2–4 元 n-gram + 多项式朴素贝叶斯，流水线训练后 joblib 落盘，进程内单例懒加载。
- **三层兜底**：模型置信度 ≥ 0.6 采纳模型标签；低于阈值或模型缺失/损坏/推理异常时，静默降级到确定性关键词规则；再上游由大模型仲裁。任何一层失效都不阻断对话。
- **封闭标签空间**：闲聊、文档、表格、配图、图片理解、风险拦截六类，并映射到对应产物动作（docx / csv / png / 无产物）。
- **可解释留痕**：每条决策记录标签、置信度、命中层级、关键词、耗时；前端面板展示模型状态、离线指标对比与最近决策明细。

### 3.3 产物本地化生成与零成本朗读

- 按意图在本地渲染文档（docx）、表格（csv）、示意图（png），产物与文字挂在同一条助手消息上，前端复用附件卡片渲染图片与文件。
- 语音朗读使用浏览器 `speechSynthesis`，不经过后端、不调用语音 API，卸载时自动取消；无额外服务端成本。

### 3.4 工程化治理体系

- **积分治理**：按输入/输出/图片数估算费用；团队链路按回复人数预检，余额不足在调用大模型前拦截；扣费写流水，失败中断后续成员回复。
- **配置与审计**：系统动态配置可覆盖运行参数；后台关键写操作留审计日志；角色权限区分普通用户 / 管理员 / God。
- **安全与稳健**：风险守门关键词拦截、接口限流、错误回复落库、流式中断时已生成内容优先保存。
- **知识挂载**：智能体可绑定知识库文档，注入对应上下文。

### 3.5 可评测、可复盘

- 离线评测在验证集上对比三层链路与纯规则基线的准确率、宏 F1，并统计单条平均耗时；评测脚本可随数据集扩充复跑。
- 决策日志与审计日志构成过程回放依据，答辩或复盘时可逐条追溯"为什么这么路由"。

## 四、优势（对比常见纯大模型方案）

| 维度 | 本项目做法 | 带来的优势 |
| --- | --- | --- |
| 成本 | @ 触发才调 LLM、调用前积分预检、本地先做路由决策 | 减少无效大模型调用，费用可控 |
| 稳健性 | 三层兜底、模型失效降级规则、离线可跑、错误落库 | 单点故障不崩溃，演示环境抗造 |
| 可追溯 | 决策标签/置信度/层级/耗时留痕，面板可复盘 | 决策过程可解释、可审计 |
| 部署门槛 | CPU、SQLite、无重型深度学习依赖 | 学生机、轻量云服务器即可运行 |
| 可扩展性 | Skill 仓库、技能绑定、知识库、模型接口可插拔 | 后续加能力不改主干 |
| 工程质量 | 前后端均有回归测试基线，核心流程有定向用例 | 迭代不破坏既有契约 |
| 多模态 | 图片上传可进入大模型上下文，配图意图可路由 | 覆盖图文混合诉求 |

## 五、项目意义

### 5.1 技术意义

把多智能体协作从"提示词拼装"推进到**有本地决策、可量化评测、可解释追溯**的分层系统：本地轻量模型承担高频路由，规则层保底，大模型只在需要生成时介入。这验证了在小样本、受限算力下，"轻量 ML + 规则兜底 + 大模型仲裁"是一条务实且可落地的技术路线。

### 5.2 场景意义

为教育研讨、头脑风暴、专家访谈、小组协作提供了数字化载体：专家角色可创建、复用、绑定技能与知识；讨论过程可回放、产物可留存，适合教学演示与课题实验。

### 5.3 竞赛与展示意义

呈现的是一条**完整工程闭环**——架构分层、编排调度、决策内核、离线评测、前端交互、成本治理、部署与测试，而非单点功能 Demo。分层降级、决策可解释、指标可对比，是答辩中容易讲出深度的技术亮点。

### 5.4 演进意义

当前接口为后续升级留出空间：更强分类器/小蒸馏模型替换路由层、向量记忆检索、多智能体协同决策策略、更丰富的产物类型，都可在既有骨架上增量接入。

## 六、客观边界（答辩防追问）

- **样本规模有限**：种子集 90 条（训练 72 / 验证 18），部分类别在验证集中样本为 0，离线指标仅供链路对比参考，扩充标注后才更稳定。
- **接入范围**：决策小模型当前已接入团队群聊链路；单聊、圆桌发言打分复用同一接口属于已预留的扩展点。
- **生成依赖云端**：本地只做路由与兜底，内容生成质量仍取决于云端大模型；本地不产出文本。
- **本次明确未做**：深度模型 / 大模型 LoRA 微调、强化学习 / 自博弈、向量记忆检索、真实文生图、服务端 TTS、模型蒸馏的精度-成本曲线。
