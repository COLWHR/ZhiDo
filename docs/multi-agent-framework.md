# ZhiDo / MADF 多智能体框架设计文档

> 版本：V1.2.1 ｜ 口径：基于当前仓库代码与实测回归结果撰写，不含未落地的规划功能。
> 适用：课程答辩、老师技术评审、竞赛备赛讲解。

## 一、框架概述

### 1.1 定位

ZhiDo（内部代号 MADF，Multi-Agent Discussion Framework）是一个面向**研讨、教育与头脑风暴**场景的多智能体协作 Web 平台。用户可以创建专家型智能体（Persona），围绕一个主题组织**圆桌讨论、团队群聊或一对一持续对话**；框架负责发言调度、意图路由、上下文装配、产物生成、成本治理与全过程留痕。

一句话概括框架思想：

> **云端大模型负责内容生成，本地规则与轻量小模型负责决策路由与兜底；框架把"多智能体各自思考—竞争发言—协作接力—沉淀产物"做成了一套可部署、可评测、可追溯的工程闭环。**

### 1.2 设计目标

| 目标 | 框架上的落地手段 |
| --- | --- |
| 角色可定义、可复用 | 人设卡（Persona）数据化：头衔、生平、理论武库、立场、系统提示词、技能、知识库均可配置与挂载 |
| 多形态协作 | 同一套智能体抽象支撑圆桌论坛、团队群聊、单聊三种编排模式 |
| 决策可解释、可评测 | 本地意图路由小模型 + 规则兜底 + 大模型仲裁，每次决策落审计、可复算指标 |
| 成本可控 | @ 触发才调大模型、调用前积分预检、发言公平性与成本因子进入调度打分 |
| 稳健可演示 | 三层降级链路、模型失效静默兜底、离线可跑、错误落库不中断主流程 |
| 便于扩展 | 分类器接口、技能仓库、知识库、模型供应商均可插拔，不动主干业务 |

### 1.3 与"纯提示词拼装"方案的区别

多数演示型多智能体项目停留在"每个角色一段 system prompt + 直接问大模型"。本框架在此之上补齐了四层工程能力：

1. **显式的智能体抽象**：元智能体（造角色）、主持人、嘉宾、成员四类角色各有独立职责、记忆与行为方法；
2. **可计算的调度机制**：圆桌发言不是随机轮流，而是经过"思考申请 → 多因子打分排序 → 约束校验 → 兜底选人"的确定性流程；
3. **分层决策内核**：高频的意图判断由本地轻量模型与规则承担，大模型只在需要生成内容时介入；
4. **全链路留痕与评测**：决策记录、轮次记录、审计日志、离线评测指标构成可复盘依据。

### 2.2 技术栈

- **前端**：Vue 3 + TypeScript + Vite + Pinia + Vue Router + Ant Design Vue；SSE / WebSocket 流式渲染、@ 提及弹层、附件卡片、浏览器端语音朗读（`speechSynthesis`，不经过后端）。
- **后端**：FastAPI + Uvicorn；REST API + 实时推送；JWT 鉴权；分层结构（端点 → 编排服务 → 决策/规则/模型 → 数据层）。
- **数据层**：libsql（SQLite）/ PostgreSQL 双库兼容；可选 Redis 做日志缓冲与缓存。
- **模型层**：云端大模型（GLM 系列）承担文本生成与图片理解；本地不部署深度学习模型。
- **质量保障**：后端 Pytest，前端 Vitest。当前回归基线：后端 **159 passed**，前端 **37 passed / 1 skipped**。

## 三、智能体角色体系

框架在 `app/agent/` 下定义统一抽象，并派生四类职责不同的智能体。

### 3.1 角色总览

| 角色 | 代码载体 | 定位 | 核心行为 | 记忆 |
| --- | --- | --- | --- | --- |
| 元智能体（角色工厂） | `God` / `RealGodAgent` | 从自然语言需求生成一批有深度的专家人设 | 数量推断 →（联网检索）→ 结构化 Persona 产出；RealGod 走 ReAct 循环 | 会话内去重上下文 |
| 主持人 | `ModeratorAgent` | 引导节奏、提炼观点、收口 | 开场 `opening`、阶段总结 `periodic_summary`、闭幕 `closing` | 共享摘要历史 |
| 嘉宾智能体 | `ParticipantAgent` | 独立视角参与讨论 | 快思考 `think`（是否发言 / 优先级 / 风格）→ 发言 `speak`（流式） | 私有记忆 + 共享记忆 |
| 成员 / 单聊智能体 | 编排服务装配 Persona | 团队被 @ 后接力发言，或与用户持续对话 | 上下文装配 → 技能路由 → 流式回复 → 产物挂载 | 会话历史持久化 |

### 3.2 基础抽象 `BaseAgent`

所有智能体持有最基本的两个属性：`name`（身份名）与 `system_prompt`（第一人称扮演提示词）。具体角色在此之上扩展自己的领域属性与行为方法。

### 3.3 元智能体：从需求到专家人设

**两条实现路径：**

- `God`：纯提示词批量生成。先由一次轻量调用推断角色数量，再让大模型按固定 JSON Schema 产出人设列表（姓名、头衔、300 字生平、7 条理论武库、立场、系统提示词）。
- `RealGodAgent`：带工具的 **ReAct（Thought → Action → Observation）** 循环。
  - **Thought**：分析需要补充什么信息，先宽搜定原型、再深搜补细节；
  - **Action**：`Search[关键词]` 联网检索，或 `Finish[JSON]` 提交人设；
  - **Observation**：把检索结果回灌上下文，进入下一轮思考；
  - 单次角色最多 2 次搜索，达到上限强制 `Finish`。

**防重复机制**：本轮已生成角色名、数据库已有角色名都会注入提示词上下文，明确禁止重复生成或"深化补充"已有角色。产出字段包含 `name / title / bio / theories / stance / system_prompt`，落库后即可被圆桌、团队、单聊复用。

### 3.4 主持人 `ModeratorAgent`

主持人不参与观点竞争，负责流程控制：

- **开场**：欢迎、介绍主题背景、介绍嘉宾名单、宣布论坛开始；
- **阶段总结**：每积累一个发言窗口，提炼各嘉宾核心观点，写入摘要历史；
- **闭幕**：综合各阶段总结，按"讨论脉络 → 共识 → 分歧 → 未解决问题"四段式收口，并宣布结束。

### 3.5 嘉宾智能体 `ParticipantAgent`

嘉宾是框架中行为最完整的角色，拆成**思考**与**发言**两个阶段：

**人设属性**：头衔 `title`、生平 `bio`、理论武库 `theories`、立场 `stance`、专属知识库 `knowledge_text`、发言优先级 `priority`、发言状态机（是否已发言 `has_spoken`、上次发言轮次 `last_spoken_turn`、累计发言数 `speech_count`）。

**快思考 `think(context)`**：
- 输入：当前环境上下文、私有记忆、生平与理论武库、专属知识库；
- 要求模型输出结构化 JSON：`inner_monologue`（第一人称内心判断）、`decision`（`APPLY_SPEAK` / `LISTEN`）、`priority`（0–100）、`focus`（本轮最该回应的核心请求）、`style`（回答 / 澄清 / 质疑 / 总结 / 支持）；
- 工程约束：短 JSON、低温度、紧超时、单次重试，避免选人环节卡住整轮；
- 解析容错：正则抽取 JSON、缺失字段回退默认值，模型异常时返回保守的 `listen` 结论。

**发言 `speak(thought, context)`**：
- 依据思考结论与表达风格生成口语化发言；
- 风格提示按 `answer / clarify / challenge / synthesis / support` 分别给出表达策略；
- 首次发言允许简短自我介绍，复发言不再重复；
- 返回流式生成器，由编排层逐 token 广播。

**表达风格归一化**：模型原始输出可能是英文或中文措辞，框架统一映射到五种风格枚举，供调度打分与提示词使用。

### 3.6 成员 / 单聊智能体

这两类不另设重型类，由编排服务把 Persona 字典装配成模型消息：

- **团队成员**：仅在被 @ 时触发，按顺序接力，后发言者可见同轮前面成员的回复；
- **单聊智能体**：与用户维持持续对话，历史持久化，上传图片可进入多模态上下文。

## 四、记忆与上下文机制

框架区分**共享记忆**与**私有记忆**两级，并在持久化层做长期留存。

### 4.1 共享记忆 `SharedMemory`

服务于圆桌全体嘉宾的公共上下文：

- **上下文窗口**：`deque` 定长队列，保留最近若干条发言；
- **摘要缓冲**：累计达到窗口大小即触发一次阶段总结；
- **摘要历史**：历次阶段总结长期保留；
- **全量历史**：所有发言留存备查。

对外提供 `get_context_str()`，拼装为"【过往总结】+【近期讨论】"两段文本注入下一轮上下文。

### 4.2 私有记忆 `PrivateMemory`

每个嘉宾独立持有：

- **思考历史**：近期思考结论（焦点、动作、风格），定长淘汰；
- **发言历史**：本人过往发言，发言时带回最近 3 条，保持个人观点连贯、避免自我重复。

### 4.3 持久化与上下文装配

- 消息、思考历史、摘要历史均落库；论坛重启后可从库中恢复嘉宾私有记忆。
- 团队/单聊在进模型前由编排服务装配上下文：**过滤 system 类型的界面提示消息**（不能当作历史发言回灌模型）、保留附件、按最大条数截断最近上下文。
- 知识库文本单独成段注入，提示模型"优先参考资料，资料未覆盖再依靠通用认知，不要编造"。

### 4.4 记忆与消融开关

调度器支持一组消融标志（`ablation_flags`），可在实验中关闭某类记忆或机制以对照效果：`no_private_memory`（关私有记忆）、`no_shared_memory`（关共享记忆）、`no_summary`（关阶段总结）等。

## 五、协作编排模式

框架用三种编排服务承载三种协作形态，彼此隔离数据表、CRUD 与接口，只复用智能体抽象与决策内核。

### 5.1 圆桌论坛：调度器主导的竞争发言

`ForumScheduler` 是框架最核心的编排组件，主循环每轮执行以下流程：

```text
1. 观众消息优先处理
   有新插话 → 清空当前发言队列，带新上下文重新思考
2. 风险前置门控
   风险分级 L0–L3；L3 高风险由"安全守门"直接接管，L2 注入稳定/澄清提示
3. 上下文重建
   从库中取消息 → 重建共享记忆 → 同步各嘉宾私有记忆 → 推断本轮表达模式
4. 并行思考
   所有嘉宾并发 think；0.5s 轮询、可被观众插话中断；思考期间新消息会作废陈旧结论
5. 候选打分排序
   对申请发言者计算多因子得分，排序生成发言队列
6. 约束校验选人
   禁止连续同一人发言；队列无人满足时走确定性兜底选人
7. 流式发言与落库
   选中嘉宾 speak → 逐 token WebSocket 广播 → 落库 → 积分扣费 → 写轮次记录
8. 轮次与成本闸门
   达最大轮数自动收尾；周期性 WAL 检查点；批量刷写系统日志
```

#### 5.1.1 发言打分因子

调度器 `_estimate_candidate_score` 在模型给出的优先级基础上，叠加多组确定性因子（得分裁剪到 0–100）：

| 因子 | 作用方向 | 说明 |
| --- | --- | --- |
| 模型优先级 | 正向 | 思考结论自带的 `priority` 作为基准分 |
| 上下文相关性 | 正向 | 与近期发言共享关键词越多，加分越明显（封顶） |
| 问题回应倾向 | 正向 | 思考内容指向"问题/观众/追问/回应"时加分 |
| 提问回合适配 | 正向 | 上一轮是提问且嘉宾风格为回答/澄清时加分 |
| 表达模式匹配 | 正向 | 本轮模式（回答/澄清/质疑/总结/过渡）与嘉宾风格一致时加分 |
| 重复发言惩罚 | 负向 | 上一位发言者大幅降分；本轮已发言者降分；间隔过短重罚 |
| 发言间隔补偿 | 正向 | 长时间未发言者获得小幅补偿 |
| 成本公平因子 `f_cost` | 双向 | 累计发言超过公平份额者边际扣分，调用较少者小幅补偿 |
| 观点新颖度 `f_nov` | 正向 | 候选思路中近期未出现的新词占比越高，奖励越多（奖励新信息） |
| 重复度 `f_div` | 负向 | 与近期某条发言高度相似（Jaccard ≥ 0.5）时惩罚"老调重弹" |

新颖度与多样性视角不同：前者对照近期发言**并集**看新词比例，后者对照**单条最相似发言**看归一化相似度。

#### 5.1.2 兜底与稳健性

- 无人申请发言时，按本轮表达模式构造兜底思考，在全量嘉宾中重新打分选人；
- 仍无候选时回退到首位参与者，保证流程不卡死；
- 思考失败、发言空返回、模型异常都有对应日志与保守路径，不向上抛出导致主循环崩溃；
- 并发上限（`MAX_CONCURRENT_FORUMS`）、最大轮数（`MAX_FORUM_TURNS`）双重防止资源失控。

#### 5.1.3 观众插话与可中断思考

- 观众消息进入独立异步队列，每轮开头、思考前、思考中、发言前多个节点检测；
- 思考阶段被插话会取消未完成的思考任务，作废陈旧结论；
- 发言流式过程中被插话，中断当前生成并保留已生成内容。

### 5.2 团队群聊：@ 触发的上下文接力

团队模块独立成表与 SSE 接口，编排要点：

- **@ 解析**：客户端显式提交的 `mentioned_persona_ids` 优先；未解析到的名字再用正则从文本中 `@成员名` 兜底匹配；非法/非成员 ID 静默丢弃。
- **按需调用**：未被 @ 的成员不调用大模型，从源头减少无效 token。
- **上下文接力**：历史消息转成 `{speaker, content, attachments}` 结构，过滤 system 提示，保留最近若干条；多成员按顺序回复，后发言者可见同轮前序回复。
- **决策接入**：本轮诉求先经决策内核路由，产物类型优先取决策结果、规则判定兜底；SSE 通过 `decision` 事件下发标签、置信度、层级、关键词、耗时。
- **成本预检**：按回复人数预估费用，余额不足在调用大模型前拦截（402）；扣费写流水，失败则中断后续成员回复。

### 5.3 单聊：持续对话与多模态

- 单个智能体与用户维持多轮对话，历史持久化、可清空；
- 上传图片进入多模态上下文，按图片数量启用多模态模型；
- 回复流式返回，产物（文档/表格/配图）挂在同一条助手消息上；
- 提供非流式 `chat` 与流式 `chat/stream` 两条入口，历史查询与消息留存独立成接口。

## 六、决策与路由内核

### 6.1 三层决策链路

意图路由采用"模型达标 → 规则兜底 → 大模型仲裁上游"的三层结构：

```text
用户诉求 text
   │
   ├─ 第 1 层：本地 ML 分类器（TF-IDF + 多项式朴素贝叶斯）
   │      ├─ 置信度 ≥ 0.6 → 采纳模型标签（layer = model）
   │      └─ 置信度 < 0.6  → 转入第 2 层
   │
   ├─ 第 2 层：确定性关键词规则基线（layer = rule）
   │      模型缺失 / 损坏 / 推理异常时，直接由本层兜底
   │
   └─ 第 3 层：上游大模型仲裁（既有 LLM 链路，不在本地模型范围内）
```

设计要点：

- **永不抛异常**：模型文件缺失、损坏或推理出错时静默降级规则层，聊天流程不中断；
- **置信度门槛**：低置信度不强行决策，交给更可控的规则层；
- **可插拔**：分类器对外固定为 `predict(text) -> 决策结果`，后续可替换为逻辑回归或小蒸馏模型而不改上层业务。

### 6.2 封闭标签空间与产物动作

| 标签 | 含义 | 回复产物 |
| --- | --- | --- |
| `chat` | 闲聊 / 通用问答 | 无（纯文本） |
| `doc` | 文档 / 报告 / 方案 / 总结 / 讲稿 | `docx` |
| `sheet` | 表格 / 清单 / 对比表 / 统计表 | `csv` |
| `image` | 配图 / 示意图 / 流程图 / 思维导图 | `png` |
| `vision` | 理解上传图片（读图 / 识别图中内容） | 无（走多模态） |
| `risk` | 敏感 / 不安全诉求 | 无（风险拦截） |

规则基线按"风险 → 图片理解 → 配图 → 表格 → 文档 → 闲聊"的优先级匹配，更具体的标签先命中。

### 6.3 本地模型选型

- **特征**：`TfidfVectorizer`，字符级滑窗（`char_wb`），2–4 元字符 n-gram，适配中文短诉求、不依赖分词词典；
- **分类器**：`MultinomialNB`（alpha = 0.1），轻量稳定；
- **流水线**：特征提取 → 分类器整体用 `joblib` 落盘；进程内单例懒加载，只加载一次；
- **样本**：种子集 90 条（训练 72 / 验证 18，固定随机种子 42，可复现），落盘 `data/intent_dataset.csv`，权重 `models/intent_router.joblib`。

**为何不选深度学习 / LoRA**：备赛周期与算力受限（纯 CPU、短周期），历史日志样本少；深度模型在小样本下易过拟合、训练部署成本高、现场离线不可控。朴素贝叶斯 + TF-IDF 在短文本意图分类上性价比高、毫秒级推理、权重可随包离线分发；样本积累后可平滑替换。

### 6.4 离线评测结果

验证集（18 条）上对比三层链路与纯规则基线：

| 决策链路 | 准确率 Accuracy | 宏 F1 |
| --- | --- | --- |
| 三层链路（小模型 + 规则兜底） | **0.8333** | **0.6983** |
| 纯规则基线 | 0.7778 | 0.6611 |

- 三层链路相对规则基线：准确率 +5.55 个百分点，宏 F1 +0.0372；
- 本地推理平均耗时毫秒级（约 1.2–3.4 ms / 条，不含网络调用）；
- 评测脚本可在扩充数据集后复跑。

> 说明：种子集规模偏小，部分类别在验证集中样本为 0，离线指标仅供链路对比参考；扩充标注样本后指标会进一步稳定。

### 6.5 大模型分层路由

在决策内核之外，模型层本身按职责分层（详见 `docs/llm-routing-strategy.md`）：

| 层 | 用途 | 调用策略 |
| --- | --- | --- |
| A 强推理 | 复杂分析、多约束规划、论坛总结裁决 | 低频、仅高价值场景 |
| B 主力对话 | 日常单聊、论坛常规发言、一般问答 | 默认层，承担多数请求 |
| C 廉价 / 摘要 | 意图识别、历史摘要、长上下文压缩、失败兜底 | 高频短任务 |
| D 多模态 | 图片理解、图文混合上下文 | 仅在有图片时启用 |

路由总流程：轻量分类 / 规则判断 → 是否需要深度思考 → 选层生成 → 结果检查 → 不满足则澄清或升级；失败按"强模型 → 主力 → 廉价 → 固定兜底话术"逐级降级。

### 6.6 技能运行时

`skill_runtime` 负责把 Persona 与上下文装配成模型消息，并做本地产物渲染：

- **技能推断** `infer_skill_route`：结合人设技能、上下文、附件推断本轮路由；
- **消息装配** `build_llm_messages`：合并系统提示词、人设、知识库、历史与附件；
- **产物渲染**：`render_text_artifact`（docx）、`render_csv_artifact`（csv）、`render_png_artifact`（png），产物与文字挂在同一条消息上；
- **附件处理**：类型识别、文本抽取、摘要、安全存储路径、公开 URL 生成。

## 七、通信与事件流

### 7.1 三种通信通道

| 通道 | 用途 | 典型场景 |
| --- | --- | --- |
| REST API | 资源读写、鉴权、配置、历史查询 | 登录、建人设、拉取决策概览 |
| SSE（`text/event-stream`） | 单连接流式文本推送 | 单聊、团队群聊逐字回复、产物事件 |
| WebSocket | 多端广播、近似直播 | 圆桌发言 chunk、系统日志、状态更新 |

### 7.2 主要事件类型

| 事件 | 通道 | 载荷要点 |
| --- | --- | --- |
| `message_chunk` | WebSocket | 发言片段、发言人、persona/moderator、stream_id、内心思考 |
| `new_message` | WebSocket | 完整消息、内容、思考、时间戳 |
| `system_log` | WebSocket | 时间戳、级别、内容、来源（思考 / 发言 / 提示 / 错误） |
| `status_update` | WebSocket | 论坛运行 / 关闭状态 |
| `content` | SSE | 单聊 / 团队回复文本片段 |
| `artifact` | SSE | 本轮生成的产物（文件 / 图片） |
| `decision` | SSE | 标签、置信度、层级、关键词、耗时 |
| `error` | SSE | 错误类型与可读信息 |

### 7.3 广播与持久化解耦

圆桌系统日志采用"先广播、后落库"：WebSocket 立即推送保证前端感知速度，落库走后台任务；Redis 缓冲失败时回退到线程内直写数据库。批量日志定期刷库，避免每条写库阻塞主发言链路。

## 八、治理、安全与可靠性

### 8.1 积分治理

- **估算**：按输入 / 输出 token、图片数估算费用；
- **预检**：论坛开启前、团队回复前、单聊调用前做余额校验，不足则在调用大模型前拦截；
- **扣费**：发言后写积分流水，标注场景与关联对象；扣费失败不回溯主流程，但记录告警。

### 8.2 风险门控

`duxin_risk_service` 在圆桌发言前做风险分级：

| 级别 | 处置 |
| --- | --- |
| L0 普通 | 进入正常候选排序 |
| L2 潜在风险 | 注入"优先稳定情绪、澄清边界、避免讨论危险细节"的提示 |
| L3 高风险 | 绕过普通排序，"安全守门"角色直接接管，输出危机回应并记录升级事件 |

### 8.3 权限与安全

- 账号角色分 `user / admin / god`；公开注册接口不能自选高权限，未开启角色选择时一律降级为普通用户并留日志；
- 接口限流；附件归属校验（头像 / 知识库只能使用本人附件）；
- 关键写操作留审计日志；错误回复落库便于排查。

### 8.4 降级与离线预案

| 异常情形 | 行为 |
| --- | --- |
| 决策模型文件不存在 / 损坏 / 推理异常 | 静默降级规则层，链路不中断 |
| 大模型 401 / 403 / 429 / timeout / 网络错误 / 空返回 | 同级重试 → 降级备用模型 → 固定兜底话术 |
| 现场无外网 | 决策权重本地打包，本地推理不依赖外网；仅上游内容生成需要联网 |
| 流式中断 | 已生成内容优先保存，不丢前序片段 |
| 样本不足 | 退化为增强规则，保留"分层决策 + 可插拔模型接口"的架构价值 |

### 8.5 并发与资源控制

- 同时运行论坛数有上限；
- 论坛最大轮数闸门防止无限调用大模型；
- 数据库连接按操作 / 逻辑块开闭，不长时间持有连接；
- SQLite 周期性 WAL checkpoint，控制单文件膨胀。

## 九、框架亮点与创新点

1. **"思考—发言"两阶段嘉宾模型**：嘉宾先低成本判断是否发言、以什么风格发言，再生成内容；决策与生成分离，便于独立评测与降级。
2. **可计算、可解释的调度打分**：发言人选不是随机轮流，而是优先级、相关性、模式匹配、公平性、成本、新颖度、多样性等多因子加权，并保留惩罚/补偿依据。
3. **两级记忆 + 可消融实验**：共享记忆沉淀公共脉络，私有记忆保持个人连贯；各记忆组件可独立关闭做对照实验。
4. **本地可训练、可评测的决策内核**：小样本、纯 CPU 即可训练与离线推理，三层兜底保证可用性，离线指标可复算、决策过程可追溯。
5. **成本内建到框架层**：@ 触发、调用前预检、发言公平因子、轮数上限、模型分层路由，从多个环节压缩无效 token。
6. **ReAct 元智能体造角色**：带联网检索与防重复约束，产出结构化、可复用的专家人设，而不是一次性提示词。
7. **全链路留痕可复盘**：决策日志、轮次记录、系统审计、积分流水共同构成过程回放依据，答辩时可逐条追溯"为什么这么路由、为什么选这个人发言"。
